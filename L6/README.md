# 第六章：智能体框架开发实践

第六章的核心目标，是完成一次开发思维升级：从手写单个 Agent 的循环逻辑，
转向使用成熟框架组织模型、角色、消息、状态、工具、终止条件和运行生命周期。

本章的重点不是记住四套 API，而是理解四种不同的系统设计哲学，并能根据业务
约束选择合适的框架。

> `L6-1` 是“从手动实现到框架开发”的概念导论，没有独立本地实践目录；本地案例
> 从 `L6-2` 开始。

## 本章主要教学目标

完成本章后，应能够：

1. 解释框架相对于一次性 Agent 脚本解决了哪些复用、协作、状态和工程问题。
2. 区分对话驱动、消息驱动、角色扮演和状态图四种编排范式。
3. 为多 Agent 系统定义角色职责、共享上下文、发言或执行顺序及终止条件。
4. 判断任务更需要自主涌现、显式控制，还是生产级工程能力。
5. 根据规模、流程确定性、可观测性和部署要求完成框架选型。

## 四个实践的共同基础

四个框架采用不同抽象，但都在处理同一组核心问题：

```text
用户任务
  → 模型适配
  → 角色或执行节点
  → 上下文与中间状态
  → 协作或工作流编排
  → 终止与结果输出
  → 错误处理和可观测性
```

因此，学习时应把注意力放在“同一个问题由不同框架如何表达”，而不是只比较代码
长短。

## 框架差异对比

| 维度 | AutoGen | AgentScope | CAMEL | LangGraph |
|---|---|---|---|---|
| 核心抽象 | 可对话 Agent 与 Team | Agent、消息中心和运行平台 | 互补角色与 RolePlaying 会话 | State、Node、Edge 构成的状态图 |
| 协作方式 | 多角色群聊、轮询或动态选人 | 消息驱动的多 Agent 协作 | 双角色自主对话 | 节点按图和条件边执行 |
| 控制方式 | 对话规则与终止条件 | 生命周期与消息基础设施 | 初始提示和角色约束 | 显式流程、分支和循环 |
| 状态表达 | 共享对话历史 | 消息、Agent 状态与平台能力 | 角色会话历史 | 显式共享 State |
| 可预测性 | 中等，取决于团队调度 | 中高，工程机制更完整 | 较低，更依赖提示涌现 | 高，路径和状态转换清晰 |
| 工程化重点 | 多 Agent 协作组合 | 并发、分布式、容错、可观测性 | 低代码量的深度协作 | 可追踪、可审计的工作流控制 |
| 最适场景 | 软件团队、评审、多人决策 | 长期运行的大规模多 Agent 应用 | 两位专家共同创作或研究 | 审批、反思、生成—测试—修复循环 |
| 本地案例 | 软件开发团队 | 三国狼人杀 | 心理学电子书写作 | Tavily 智能搜索助手 |
| 主要优势 | 角色扩展和对话路由灵活 | 生产工程能力完整 | 角色协作直观、代码轻量 | 流程确定、状态清晰、循环自然 |
| 主要限制 | 对话增长后成本和调试复杂 | 学习和部署概念较多 | 高度依赖角色提示质量 | 需要开发者明确设计图与状态 |

## 两个关键权衡

### 1. 涌现式协作与显式控制

- CAMEL 更强调角色与目标，让协作行为从对话中涌现。
- AutoGen 在涌现式对话之上增加团队调度、选人和终止规则。
- LangGraph 要求显式声明节点、边、分支和循环，以可控性换取设计成本。
- AgentScope 不只回答“怎样协作”，还重点回答“怎样让协作系统稳定运行”。

### 2. 实验原型与生产工程化

- CAMEL 适合快速验证两位专家是否能够产生高质量协作。
- AutoGen 适合快速组织多角色团队并迭代交互协议。
- LangGraph 适合需要确定执行路径、回退、审计的业务流程。
- AgentScope 适合把多 Agent 从可运行原型推向并发、分布式和可观测服务。

这些维度并非绝对排名。例如，AgentScope 也能实现灵活对话，AutoGen 也能配置严格
流程；对比表强调的是各框架最突出的设计重心。

## 建议学习顺序

1. [L6-2 AutoGen](./L6-2/AutoGen/README.md)：理解 Agent、共享模型客户端、Team、消息流和终止条件。
2. [L6-3 AgentScope](./L6-3/AgentScope/README.md)：观察消息中心、结构化输出和复杂游戏生命周期。
3. [L6-4 CAMEL](./L6-4/CAMEL/LEARNING_DIAGRAMS.md)：用最少编排代码体验双角色自主协作。
4. [L6-5 LangGraph](./L6-5/LangGraph/LEARNING_DIAGRAMS.md)：把 LLM、搜索与答案生成显式建模为状态图。

每个实践目录均包含：

- `LEARNING_DIAGRAMS.md`：7 类中文设计图及讲解。
- `diagrams/`：可编辑 `.mmd` 源文件和可直接打开的 `.svg` 成品图。
- `.env.example`：统一 DeepSeek 配置模板。
- `requirements.txt`：独立依赖清单。
